# Demonstration plan

No public recording or interactive service is available in this release. The intended first demonstration is a recorded walkthrough using synthetic profiles and simulated conditions.

| Sequence | What the viewer sees | Capability illustrated |
| --- | --- | --- |
| Select a scenario | A labeled demo flag and associated conditions | Scenario-driven application state |
| Explore Today | Before/during/after content and read-aloud controls | Information design and accessibility |
| Ask a simple flag question | A deterministic answer without generation | Rules-first routing |
| Ask a complex planning question | An actual model response based on selected context | AI orchestration |
| Exercise a reviewed boundary case | A rule bypass or targeted response correction | Inspectable control paths |
| Browse resources | Categories and scenario-derived availability | Backend-to-mobile directory workflow |
| View proposed extensions | Schematic map and simulated buddy interactions | Product direction, clearly labeled as proposed |

The recording must visibly distinguish simulations from real information. A simulated notification must never be presented as delivered. Example outputs should come from actual execution; illustrative expected behavior is not a result.

Before recording, revise the unavailable-data behavior and misleading live or safety badges, review the demonstration facts, and verify that no participant information, credentials, or internal configuration is visible.

An interactive demo is a later step. It should use an isolated environment, bounded usage, and synthetic inputs. Screenshots, sample questions, and a demonstration link can be added after the relevant workflow has been verified.
